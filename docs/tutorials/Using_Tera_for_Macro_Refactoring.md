# Tutorial: Automating Code Refactoring with Tera and Regexes

This tutorial guides you through using the `type-reporter` tool to automate code refactoring, specifically by identifying generic type patterns in Rust code and generating macro-based replacements using Tera templates and regular expressions.

## 1. Introduction

Modern codebases often involve complex generic patterns, especially in systems programming languages like Rust. Manually refactoring these patterns can be tedious and error-prone. This tutorial demonstrates a toolchain that leverages `grep` for initial pattern identification, Rust's `regex` crate for precise argument extraction, and the `tera` templating engine for generating macro-based code replacements.

Our goal is to transform code like:
```rust
pub fn new(cx: &'a mut crate::base::ExtCtxt<'b, DRT>, monotonic: bool) -> Self {
    MacroExpander { cx, monotonic }
}
```
into something like:
```rust
pub fn new(cx: CtxSpecial!('a', 'b', DRT), monotonic: bool) -> Self {
    MacroExpander { cx, monotonic }
}
```
This is achieved by extracting lifetimes (`'a'`, `'b'`) and type parameters (`DRT`) and feeding them into custom meta-macros (e.g., `CtxSpecial!`) defined in `rustc_expand_meta_macros`.

## 2. Prerequisites

Before you begin, ensure you have the following set up:

*   **Rust Toolchain**: A working Rust development environment.
*   **Project Structure**: The current workspace with the `type-reporter` project and `rustc_expand_meta_macros` crate configured as workspace members.
*   **Target File**: `submodules/rust/compiler/rustc_expand/src/expand.rs` (the file we are refactoring).
*   **Analysis Script**: `analyze_and_label_types.sh`
*   **Templates**: `templates/type_system_report.tera` and `templates/macro_refactor.tera`.

## 3. Core Concepts

*   **`analyze_and_label_types.sh`**: A bash script that uses `grep` to find occurrences of specific Rust type patterns (like `ExtCtxt`, `InvocationCollector`, `DRT`) in `expand.rs`. It outputs raw matches to `type_usage_raw.log` and labeled matches to `type_usage_labeled.log`.
*   **`type-reporter` (Rust Tool)**: A Rust binary that reads the `type_usage_raw.log` and `type_usage_labeled.log` files. It uses regular expressions to extract precise arguments (e.g., lifetimes, generic types) from the identified code contexts. It then generates:
    *   `type_usage_data.json`: A structured JSON representation of the extracted data.
    *   `type_system_report.md`: A human-readable Markdown report based on `templates/type_system_report.tera`.
    *   `generated_macro_refactors.rs`: A Rust file containing proposed macro invocations, generated from `templates/macro_refactor.tera`.
*   **`templates/macro_refactor.tera`**: A Tera template that consumes the structured data generated by `type-reporter` and outputs Rust code with macro invocations (e.g., `CtxSpecial!`, `CollectorSpecial!`, `impl_for_macro_expander!`).
*   **Regex for Extraction**: The `type-reporter` uses `regex` to capture specific parts of the code lines, allowing dynamic construction of macro arguments.

## 4. Usage Steps

Follow these steps to generate and apply macro-based refactorings:

### Step 4.1: Identify Type Usages

First, run the analysis script to identify and log the type usages in the target file:

```bash
./analyze_and_label_types.sh
```
This script will create `type_usage_raw.log` and `type_usage_labeled.log`.

### Step 4.2: Generate Structured Data and Macro Refactoring Code

Next, run the `type-reporter` Rust tool. This will process the logs, extract detailed information using regexes, and generate the various outputs:

```bash
cargo run --package type-reporter
```
Upon successful execution, you will find three new files:
*   `type_usage_data.json`: Contains the structured data about type usages, including extracted lifetimes and types.
*   `type_system_report.md`: A detailed report on the identified type usages.
*   `generated_macro_refactors.rs`: The core output for refactoring, containing Rust macro invocations.

### Step 4.3: Review Generated Macro Refactorings

Open `generated_macro_refactors.rs` and review the proposed macro invocations. This file will contain code snippets like:

```rust
// Original context (line 73): `pub fn new(cx: &'a mut crate::base::ExtCtxt<'b, DRT>, monotonic: bool) -> Self {`
//
// Proposed replacement for `ExtCtxt` usage in `pub fn new`:
pub fn new(cx: CtxSpecial!('a', 'b', DRT), monotonic: bool) -> Self { /* ... */ }
```
Pay close attention to any comments indicating manual intervention might be needed, especially for complex patterns or if the regexes couldn't fully capture all necessary arguments.

### Step 4.4: Apply Changes to `expand.rs` (Manual/Automated)

The `generated_macro_refactors.rs` file does not *directly* modify your source code. You will need to apply these changes to `submodules/rust/compiler/rustc_expand/src/expand.rs`.

**For simpler, line-based replacements:**
You could either manually copy-paste the new lines, or create targeted `sed` commands (similar to the previous `refactor_expand_rs.sh` script) that apply these specific replacements to `expand.rs`.

**For complex, multi-line block replacements (e.g., `impl MacroExpander`):**
The `impl_for_macro_expander!` macro requires the entire content of the original `impl` block. This is a multi-step process:
1.  Manually extract the content of the `impl` block from `expand.rs`.
2.  Apply any other macro-based replacements (like `CtxSpecial!`) to this extracted content.
3.  Wrap the final modified content within the `impl_for_macro_expander! { ... }` macro, using the extracted lifetimes and DRT.
4.  Replace the original `impl` block in `expand.rs` with this new macro invocation.

*(Future automation could involve a more sophisticated Rust tool that performs AST-aware transformations, or multi-line `sed` scripts, but for now, careful manual application is recommended for complex blocks).*

### Step 4.5: Compile and Verify

After applying the refactored code (either manually or via scripts), compile your project to check for errors:

```bash
cargo check # or cargo build
```
The goal is to see a reduction in compile errors, indicating successful abstraction. Any remaining errors will pinpoint areas that need further refinement in the regexes, templates, or manual intervention.

## 5. Next Steps

*   **Refine Regexes**: Continuously improve the regular expressions in `type-reporter/src/main.rs` to capture more arguments and handle more complex patterns automatically.
*   **Enhance Templates**: Develop `templates/macro_refactor.tera` further to generate even more precise and complete macro invocations.
*   **Automate Application**: Explore creating a dedicated Rust tool or advanced shell scripts that can apply the changes from `generated_macro_refactors.rs` directly to `expand.rs`, especially for multi-line block replacements.
*   **AST-based Refactoring**: For ultimate robustness, consider integrating an AST-based refactoring tool that understands Rust's syntax deeply, rather than relying solely on regex.
